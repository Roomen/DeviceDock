# DeviceDock extension contract — v1

Normative API: `sdk/index.d.ts`. Core works with zero extensions. ESM only. No global protocol state, host globals, or dependencies on sibling repositories.

## Package
A distributable directory contains `manifest.json`, `index.js` (or entry), optional relative ESM modules/assets, LICENSE and notices. Manifest example:
```json
{"schemaVersion":1,"id":"org.example.cjt188","name":"CJT188","version":"1.0.0","apiVersion":1,"kind":"protocol","entry":"index.js","platforms":["web","desktop","mobile"],"capabilities":[],"integrity":{"index.js":"sha256-<64 lowercase hex digits>"},"license":"Apache-2.0"}
```
IDs match `[a-z0-9]+(\.[a-z0-9-]+)+`; version is exact numeric SemVer (no ranges/prerelease in v1). Entry and integrity paths are normalized relative paths, no traversal, URL, query or fragment. Integrity covers EVERY executable/assets file except manifest itself and LICENSE/NOTICE. SHA-256 is content integrity, not author authenticity. Packages export `activate(host)` from entry. Protocol packages call `host.registerProtocol({id,title,create})`. Plugins may register transport or firmware services using the same host API. No default export required.

## Lifecycle and rendering
Installation validates and stores a trusted package; enable separately imports code and calls activate. Explicit user trust is required before loading local executable code. Disable first marks the extension stopping (rejecting new work), invokes registered prepareDeactivate checks, aborts host.signal, then awaits transactions, writes, returned cleanup and owned resource closure BEFORE unregistering contributions or releasing claims. Failed cleanup remains error/busy and blocks updates; retry disable is allowed. Activation failure runs the same cleanup. Every event listener, timer, worker and observer created by an extension must be disposed; use host.signal for DOM listeners. Only query/mount inside host.mount; never query global DOM. Remote same-realm JS has full page privileges: capabilities describe needs and DO NOT sandbox code. Native dynamic driver installation is unsupported.

`create({lane,mode,generation})` must return a fresh parser for each connection/lane and each replay. feed is synchronous, deterministic, ordered and returns complete frames, retaining incomplete bytes privately. reset clears all state. Never return unescaped HTML: View has plain text, label/value fields and child views only; core renders textContent. Logs use monotonic sequence, wall clock time, lane, generation, direction and copied bytes. Replay creates separate parser instances, feeds RX records oldest first, and never transfers replay state to live. No shared singleton even for SEK baselines. TX is logged after successful write.

## Sessions, resources, transactions
Each lane has an independent session generation. Open/close changes generation; queued writes and transaction operations reject stale generations. One physical port may belong to only one lane. `claim(owner)` is exclusive and reentrant only by that owner; release is idempotent. Raw UI send has no owner and is blocked while a claim exists. Transactions claim the lane, subscribe before sending, serialize writes, support timeout/caller abort, and always release in finally. Close/disable cancels transactions. Firmware extensions use transaction ownership as the update barrier; normal sends and competing power/firmware operations cannot bypass it. Extensions obtain a port only through host.resources.requestPort(providerId, options), then pass it to a host-owned session. All open/read/write/close work uses the session service; extensions never operate the underlying port directly. UI and future MCP invoke the SAME registered service; no hidden transport path.

Storage is JSON, host-namespaced by source identity and extension id; settings persist, parser/port/reconnect intent and current claims do not. Platform capability flags report actual available shell drivers, not user-agent promises. BLE/SPP/bridge are transport extensions. A desktop BLE native driver must be bundled and permissioned at shell build time; a JS package can invoke only a driver already exposed by shell. Desktop app updater is a shell service, unrelated to device firmware.

## Sources and delivery
Sources have namespace (`protocol`/`plugin`) and canonical HTTPS repository URL. Multiple sources allowed per kind; duplicates canonicalized. Source catalogs are data only: version, API, platform and SHA-256 for each release must be pinned. Installation never runs scripts or silently imports catalog URLs. V1 supports packaged local trusted modules bundled by `tools/integrate.mjs`, with immutable content directories, atomic registry switch and previous-version rollback. Runtime local JSON bundle import and remote install use a verified Service Worker cache route in browsers; the desktop shell uses an immutable native cache and `devicedock-extension` resource protocol. No remote module URL is imported directly. Source catalog caching supports offline listing; corrupt/missing cache recovers to empty, refresh failures preserve last good data. Disable before replacing/removing installed packages. Production uses copied, verified distributables inside its own build tree, never runtime symlinks or sibling imports. Future signed remote delivery must preserve trust, atomic rollback and immutable version selection.

## Delivery stages
1. Stable contract and zero-plugin host. 2. Independent CJT188 package. 3. SEK instances and replay isolation. 4. Power plugin with exclusive claims. 5. External catalog configuration. Firmware/transport boundaries already reserved. This is foundation, not a claim that all legacy tools have migrated.

## v1 clarification (integration review)
ProtocolDefinition.commands describes command fields; optional ProtocolInstance.encode({id,values}), snapshot()/restore(snapshot) provide codec and isolated state transfer. Snapshots must be owned JSON data, never references to live state. Frame.decoded has protocol/address/command/sequence/values for matching, separate from View. Namespaced business services use `protocol.<protocol-id>` for codec metadata, `plugin.<manifest-id>.<service-name>` for business APIs; registerService accepts this plugin prefix OR the canonical versioned `org.devicedock.*.v1` names below; collisions are rejected and registrations are owned by their extension (protocol metadata is host registered). Services must route UI/MCP through session transactions.

Session exposes state, connected, deviceInfo, busy and open/close with complete SerialOptions. host.resources.createSession(localId) creates a separately host-managed session for a power instrument or bridge without occupying A/B; releaseSession awaits closure. Port identity/ownership is shared across all such sessions. host.prepareDeactivate(check) registers preflight checks (throw if unsafe); returned cleanup is the async finalizer. Host waits for operations even after cancellation is requested. Transactions keep claims until callback and queued I/O actually settle; an uncooperative callback intentionally remains busy. Extension disable never falsely reports success. Host prepareForUpdate performs disable + resource drain; shell installs may proceed only after it resolves. The shell updater uses the independent DeviceDock signed-release trust contract; see release.md.

Canonical cross-repository services (final): `org.devicedock.sek.firmware.v1` (FirmwareCodecV1 as specified in Plugins/docs/service-requirements.md), `org.devicedock.power.v1`, `org.devicedock.firmware.v1`, `org.devicedock.bridge.v1`; optional shell transports `org.devicedock.native.ble.v1` and `org.devicedock.native.spp.v1` implement TransportProvider. `host.prepareDeactivate` is the canonical name; `registerBeforeDeactivate` is not an SDK method. Preflight rejection restores enabled state without aborting; retry later. Disable only cancels transactions whose owner is its own extension identity. Host overrides caller owner strings with the extension identity, preventing claim impersonation.

Runtime delivery: installer JSON is `{manifest,files}`, with base64 file contents. Browser worker independently verifies the complete relative module graph and all asset bytes, serializes installs, writes a completion marker last, and reuses complete same-hash caches. Desktop native install rechecks the canonical JSON SHA-256 and every asset SHA-256, stages into the durable app-specific data directory, then atomically renames the immutable content directory. The custom URI handler validates the hashed bundle plus requested file on every read and refuses symlinks/traversal/unlisted paths; executable bytes are never fetched from a remote URL. `__bundle.json` and `__complete` are reserved. Native HTTPS download has size/timeout/redirect/scheme/digest limits. Installation is not author authentication; enable still needs explicit trust. Previous versions are retained; host.replace rolls back activation to the last enabled version after a failed switch. Source identities do not share settings.

An enable in progress cannot be disabled until activation completes. During stopping, only the awaited finalizer may issue owner-scoped final I/O using its retained claim. A cancelled transaction retains ownership until its callback and writes settle. A timed-out physical close surfaces cleanup-needed while actual I/O continues to retain the port; closed notification and claim clearance occur only after physical release. Raw subscribers receive system connected/closing/closed events with changed generation. New parser instances are created per live connection and replay generation.

Standalone lengthless datagram protocols cannot infer boundaries from serial chunks. STS-CIU exposes createDatagram() in its package for explicit enclosing datagram integrations; the current raw serial host intentionally supplies no guessed boundaries. A standalone request rejects ordinary serial BEFORE transaction/commit/write; nested hostProto decoding and explicitly declared datagram sessions are supported. Native dynamic library installation remains unsupported. Signed application updates use the shell release contract; this is independent of verified JS package installation.

Assets: `host.assets.read(packageRootRelativePath)` returns independently verified bytes; `url(path)` returns the immutable asset URL. `await host.assets.createWorker(path, options)` reads and verifies a self-contained JS Worker entry and launches a Blob URL (no relative imports/importScripts/import.meta); pass WASM bytes from assets.read to the Worker via message/transferable. Host tracks Worker termination/Blob revocation during final cleanup. This is portable to desktop WebKit without custom-scheme Worker loading. WASM and every Worker asset must be listed in integrity. Desktop native reads reverify canonical metadata and bytes before returning; browser reads use the verified packaged/cache URL. Do not infer hardware or mobile support from the availability of a Worker.

Calling worker.terminate() immediately terminates the Worker, revokes its Blob URL, and unregisters its host cleanup callback. Disable still terminates remaining live workers. This preserves the standard Worker method signature; no extra release method is needed.


MCP: extensions explicitly register strict object schemas and optional bounded timeoutMs (1000..1800000). Context carries signal, asynchronous commit and request-bound document/lane generation snapshots. Adapters commit inside the actual owning queue, never in a generic dispatcher. Owner drain includes active tool calls. SessionService exposes readonly messageBoundary only when the open transport explicitly declares datagram, and setSignals only on the extension's dedicated resource sessions; queued signal control holds owner/generation/fence checks. Finalizers may perform owned cleanup while frozen. Core lane signal/open/close remain host-owned. See mcp.md for compatibility, structured execution status and optional attested Classic transport registration.
