# Desktop distribution and update signing

The application version comes from root package.json. Supported desktop publication targets are macOS arm64 and Windows x64. Official builds explicitly include native-ble,native-spp; drivers remain inactive until an enabled transport extension is used. CI uses macos-15, windows-2025 and ubuntu-24.04, with no moving runner aliases. The four Actions entrypoints used by these workflows were inspected upstream: checkout@v6, setup-node@v6, upload-artifact@v6 and download-artifact@v7 all run on Node 24. Rust setup uses the native rustup CLI.

Normal desktop builds are deterministic zero-plugin distributions with the two public default sources visible. They do not depend on ignored local installed.json. Explicit `DEVICEDOCK_DISTRIBUTION=integrated` builds may embed the already verified local frozen package registry; every bundle is revalidated. Neither distribution executes extensions without trust/enable. The source repositories and runtime installer provide protocol/plugin delivery after first launch.

A separate DeviceDock updater trust root is committed as desktop/updater-public-key.txt. The CLI wrapper verifies any CI public-key variable matches this file, and passes exactly that trust to the app and portable helper. Private key material is never included in source, packages, logs or artifacts. Compiler path remapping removes local build-root provenance from distributable binaries.

The release contract preserves the predecessor's Tauri/minisign mechanism: `TAURI_SIGNING_PRIVATE_KEY` repository secret, optional `TAURI_SIGNING_PRIVATE_KEY_PASSWORD`, and `TAURI_UPDATER_PUBLIC_KEY` repository variable. Independent DeviceDock signing configuration has been established. Local backup is in the owner's protected DeviceDock signing configuration directory (directory0700/files0600). Apple Developer ID/notarization is optional via APPLE_CERTIFICATE, APPLE_CERTIFICATE_PASSWORD, APPLE_SIGNING_IDENTITY, APPLE_ID, APPLE_PASSWORD and APPLE_TEAM_ID; without it macOS uses whole-bundle ad-hoc signing. No original private key is reused.

Official main releases require updater signing; missing configuration fails before publication. An unsigned local build can be manually installed, but no unsigned update is accepted. Direct Cargo startup has explicit empty updater trust configuration; production wrapper builds embed the committed public root. Windows uses portable ZIP plus independently verifying helper; signature/version binding, plan identity, process/lock ownership, byte reread and backup/rollback follow the original implementation. macOS uses the signed app updater package. The helper refuses an empty key.

Version tags are `desktop-main-v<version>` at main HEAD. The immutable version release contains platform payloads/signatures. A separate desktop-main channel manifest points to immutable assets and is promoted with backup/rollback. Preview releases use the dev channel. Preparing a version commit and pushing its tag triggers the workflow directly; main CI is not a tag prerequisite. Formal publication never automatically cancels an earlier release. Review the produced workflow artifacts and annotations before announcing delivery.

A real signer roundtrip through the portable verification library accepts the new trust root and rejects wrong version/key and tampered data. Automated native smoke exercises the multi-window update preparation/failure barrier without installing a release or touching devices. Platform CI/real release delivery is separate from local logic verification. No desktop tag or release has been created during migration acceptance.
